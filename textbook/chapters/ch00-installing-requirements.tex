\chapter{環境構築とワークフロー}

本章は，環境構築の手順とその意味を，初めて取り組む学生が確認できるように説明する。
授業用のhandoutと重なる操作も含め，OS別の導入からPythonスクリプトの実行までを本章内で扱う。
Windowsでは「環境構築 (Windows)」，Apple SiliconのMacでは「環境構築 (Mac)」を行い，その後は共通手順へ進む。
設定済みの項目は確認コマンドで状態を確かめ，成功していれば再設定しなくてよい。

\section{キーワード}

\begin{itemize}
\item \textbf{Operating System}

コンピュータ全体を管理するための基本ソフトウェア。
代表例として、Windows、macOS、Linuxがある。

\item \textbf{ファイルシステム}

ファイルやフォルダを保存し、整理し、読み書きするための仕組み。

\item \textbf{Command line interface (CLI)}

コマンドを入力してコンピュータを操作する仕組み．
操作を自動化しやすいため、開発や研究でよく使われる。

\item \textbf{ターミナル}

CLIでコンピュータを操作するためのソフトウェア

\item \textbf{テキストエディタ}

文字情報を編集するためのソフトウェア。
メモを書くための簡単なものから、
プログラムを書くための高機能なものまである。
代表例として、Visual Studio Code、Vim、Emacsなどがある。

\item \textbf{Pythonと仮想環境}

Pythonは、機械学習などで広く使われるプログラミング言語。
仮想環境は、プロジェクトごとにPythonの実行環境を分けて管理する仕組みである。

\item \textbf{Git}

ソースコードや文書の変更履歴を管理するためのバージョン管理システム。
いつ、誰が、どのような変更を加えたかを記録できる。
Gitで管理されたプロジェクトをオンラインで記録・共有
するためのサービスとしてGitHubがある．

\end{itemize}

\section{CLI操作における注意}

\begin{itemize}
\item むやみにコマンドを実行しない

\item コマンドの実行結果をよく確認する

\item エラーメッセージを無視しない

\end{itemize}

\section{環境構築 (Windows)}

この資料では，
Windows 上に Ubuntu 24.04 LTS の WSL2 環境を作成し，
その Ubuntu 上で Python と Git 操作を行うものとする。
そのため，まずはWSL2環境を構築する．

まず PowerShell を管理者権限で開き，
VS Code，Windows Terminal，WSL 本体をインストールする。

\begin{lstlisting}[style=codecell]
winget install --id Microsoft.VisualStudioCode --exact
winget install --id Microsoft.WindowsTerminal --exact
wsl --install --no-distribution
\end{lstlisting}

再起動を求められたら再起動し，PowerShellを開き直す。

\begin{lstlisting}[style=codecell]
wsl --update
wsl --version
\end{lstlisting}

\begin{itemize}
\item \texttt{wsl --install --no-distribution} 後は PC の再起動が必要になる場合がある。

\item Ubuntu 24.04 LTS 以降は新しい WSL distro format で配布されるため，\texttt{wsl --version} で WSL 2.4.10 以上になっていることを確認する。

\begin{itemize}
\item 古い場合は \texttt{wsl --update} を実行し，Windows Terminal を開き直す。

\end{itemize}

\end{itemize}

次に，インストール可能な distro 名を確認し，\texttt{Ubuntu-24.04} を明示してインストールする。

\begin{lstlisting}[style=codecell]
wsl --list --online
wsl --install -d Ubuntu-24.04
\end{lstlisting}

Ubuntu 24.04 LTS が WSL2 として入っているか，PowerShell 側で確認する。

\begin{lstlisting}[style=codecell]
wsl -l -v
\end{lstlisting}

\texttt{Ubuntu-24.04} の \texttt{VERSION} が \texttt{2} であれば WSL2 として動く。必要なら既定の distro に設定する。

\begin{lstlisting}[style=codecell]
wsl --set-default Ubuntu-24.04
wsl ~ -d Ubuntu-24.04
\end{lstlisting}

インストール後，Windows Terminal から
Ubuntu 24.04 LTS を起動する。
初回起動時には Ubuntu 側の user name と password を設定する。
password 入力中は画面に文字が表示されないが，入力自体は受け付けられている。

Ubuntu 側に入ったら，Ubuntu の release 情報も確認する。

\begin{lstlisting}[style=codecell]
cat /etc/os-release
\end{lstlisting}

\texttt{VERSION\_ID="24.04"} が確認できれば，この授業で使う Ubuntu 24.04 LTS 環境になっている。

Ubuntu を起動したら，Git，\texttt{curl}，SSHクライアントを入れる。Python 3.12は後述の \texttt{uv} で管理する。
以降の作業は，原則としてこの Ubuntu のターミナルで行う。

\begin{lstlisting}[style=codecell]
sudo apt update
sudo apt install git curl openssh-client
\end{lstlisting}

GitHub CLI (\texttt{gh}) は，GitHub への login や repository 操作をターミナルから行うために使う。
Ubuntu 24.04 LTS では，GitHub CLI の公式apt配布元を登録してからインストールする。
公開鍵ファイルはダウンロードしたパッケージの署名確認に使い，\texttt{signed-by} でそのファイルを指定する。
以下の各コマンドの成功を確認してから次の行へ進む。

\begin{lstlisting}[style=codecell]
sudo mkdir -p -m 755 /etc/apt/keyrings
sudo curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  -o /etc/apt/keyrings/githubcli-archive-keyring.gpg
sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
  | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
sudo apt update
sudo apt install gh
gh --version
\end{lstlisting}

WSL 上のディレクトリを VS Code で開くには，
Windows 側の VS Code に WSL extension が入っている必要がある。
インストールには，PowerShell で次を実行する。

\begin{lstlisting}[style=codecell]
code --install-extension ms-vscode-remote.remote-wsl
\end{lstlisting}

その後，Ubuntu 側のターミナルを開き，
次を実行できることを確認する。

\begin{lstlisting}[style=codecell]
code --version
code .
\end{lstlisting}

初回の \texttt{code .} では，WSL 側に VS Code Server が自動 install される。
\texttt{code: command not found} になる場合は，Windows Terminal と Ubuntu を開き直し，
Windows 側の VS Code と WSL extension が入っているか確認する。

\section{環境構築 (Mac)}

この手順は Apple Silicon（M シリーズ）の Mac を対象にする。
このリポジトリで固定している PyTorch 2.7.1 には Intel Mac 用の wheel がないため，
Intel Mac ではこの手順のまま環境をそろえることはできない。
Intel Mac を使う場合は，授業用に別の対応環境を用意する必要がある。

Mac では，まず，ソフトウェアをインストールするための
package manager として，Homebrew を導入する．
Terminal を開き，
Homebrew 公式ページに掲載されている以下のコマンドを実行する。

\begin{lstlisting}[style=codecell]
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
\end{lstlisting}

\begin{itemize}
\item install の途中で password の入力や Enter の入力を求められることがある。

\item install 完了時に \texttt{Next steps} として PATH 設定用の コマンドが表示された場合は，それをそのまま実行する。

\end{itemize}

次のコマンドで Homebrew が使えることを確認する。

\begin{lstlisting}[style=codecell]
brew --version
\end{lstlisting}

Homebrew が使えるようになったら，VS Code，Git，GitHub CLI をそろえる。
Python 3.12 は，後述する \texttt{uv} でインストールして管理する。
Mac に Git が入っている場合でも，\texttt{git --version} で確認してから進める。

\begin{lstlisting}[style=codecell]
brew install --cask visual-studio-code
brew install git gh
\end{lstlisting}

Mac で terminal から VS Code を開くには，
\texttt{code} command が PATH に入っている必要がある。
まず次で確認する。

\begin{lstlisting}[style=codecell]
code --version
\end{lstlisting}

\texttt{command not found: code} などと表示される場合は，
VS Code を開き，Command Palette から
\texttt{Shell Command: Install 'code' command in PATH} を実行する。
その後，Terminal を開き直して，もう一度 \texttt{code --version} を確認する。
確認できたら，作業 directory で次を実行すると VS Code が開く。

\begin{lstlisting}[style=codecell]
code .
\end{lstlisting}

\section{ターミナル操作とパス}

ターミナルでの作業には，常に「現在地」となるディレクトリ（\textbf{カレントディレクトリ}）がある。
相対パスで指定する操作はこの現在地を基準に行われるため，
まずどこにいるかを把握することが重要である。

\begin{center}
\begin{tabular}{p{0.28\linewidth}p{0.62\linewidth}}
\hline
コマンド & 役割 \\
\texttt{pwd} & 現在地のパスを表示する \\
\texttt{ls} & 現在地にあるファイルやディレクトリの一覧を表示する \\
\hline
\end{tabular}
\end{center}

\textbf{パス（path）} は，ファイルや
ディレクトリ（フォルダ）の場所を表す文字列である。
住所が分かれば建物にたどり着けるのと同じように，
パスが分かれば目的のファイルにたどり着ける。
パスは，ディレクトリ名を \textbf{\texttt{/}（スラッシュ）} でつないで書く。

\begin{center}
\begin{tabular}{p{0.28\linewidth}p{0.62\linewidth}}
\hline
記号 & 意味 \\
\texttt{/} & ディレクトリの区切り。先頭の \texttt{/} はルート（最上位） \\
\texttt{.} & カレントディレクトリ（現在地） \\
\texttt{..} & 親ディレクトリ（1つ上） \\
\texttt{\textasciitilde{}} & ホームディレクトリ（Ubuntuでは \texttt{/home/username}，Macでは \texttt{/Users/username}） \\
\hline
\end{tabular}
\end{center}

\textbf{絶対パス}：ルートディレクトリ \texttt{/} から始まるパス

\begin{lstlisting}[style=codecell]
/home/yourname/workspace/data.csv
\end{lstlisting}

\textbf{相対パス}：現在地を基準として書くパス（\texttt{/} で始めない）

\begin{lstlisting}[style=codecell]
data.csv                    # 現在地にある data.csv
outputs/log.txt             # 現在地にある outputs ディレクトリの中にある log.txt
../README.md                # 1つ上のディレクトリにある README.md
../../shared/config.yml     # 2つ上のディレクトリにある shared/ 内 の config.yml
\end{lstlisting}

現在地を別のディレクトリへ移動するには \texttt{cd} を使う。

\begin{lstlisting}[style=codecell]
cd workspace      # workspace ディレクトリへ移動
cd ..             # 1つ上のディレクトリへ戻る（.. は親ディレクトリを表す）
\end{lstlisting}

新しいディレクトリを作るには \texttt{mkdir} を使う。
\texttt{-p} オプションを付けると，
途中のディレクトリもまとめて作成される。

\begin{lstlisting}[style=codecell]
mkdir -p outputs/session01
\end{lstlisting}

\section{GitHub と Git の初期設定}

GitHub を使うには，GitHub account,
GitHub CLI の認証が必要になる。
この資料では GitHub との通信に SSH を使う前提にする。

\begin{lstlisting}[style=codecell]
gh auth login
\end{lstlisting}

\texttt{gh auth login} の質問に対して，接続先，Git通信の方式，使用するSSH鍵，認証方法を次のように選ぶ。
表示される質問や順序は，\texttt{gh} のバージョンや既存の認証・SSH 鍵の設定によって変わる。

\begin{itemize}
\item \texttt{What account do you want to log into?}: \texttt{GitHub.com}

\item \texttt{What is your preferred protocol for Git operations?}: \texttt{SSH}

\item SSH 公開鍵の登録を求められたら，使用する鍵を選ぶ。鍵がない場合は，案内に従って作成する。

\item browser を使う認証を選び，表示された code を GitHub の画面に入力する

\end{itemize}

SSH を選ぶと，\texttt{gh} は既存の SSH 鍵を探す。
適切な鍵がない場合は，新しい鍵の作成と GitHub への登録を促す。
このとき GitHub に登録されるのは公開鍵であり，
秘密鍵は自分の PC または WSL 環境の中に残る。
秘密鍵を他人に見せたり，GitHub に貼り付けたりしてはいけない。

認証と SSH key の設定が終わったら，次で状態を確認する。

\begin{lstlisting}[style=codecell]
gh auth status
ssh -T git@github.com
\end{lstlisting}

初回のSSH接続では，接続先のホスト鍵を信頼するか確認されることがある。
表示されたfingerprint（鍵の識別値）を \href{https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/githubs-ssh-key-fingerprints}{GitHub公式の公開鍵一覧} と照合し，一致した場合に \texttt{yes} を入力する。
自分のGitHubユーザー名を含む認証成功メッセージが出ればよい。
GitHubはSSHでのシェル操作を提供しないため，\texttt{ssh -T git@github.com} は認証成功時にも終了コード1を返す。
\texttt{Permission denied (publickey)} は成功ではない。使用する公開鍵が自分のGitHubアカウントに登録されているかを確認する。

Git の著者情報は次で設定する。

\begin{lstlisting}[style=codecell]
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
git config --global --list
\end{lstlisting}

\texttt{user.name} と \texttt{user.email} は commit に記録される。
自身の GitHub account と対応する情報にしておく。

\section{作業ディレクトリの作成とリポジトリの clone}

この教材では，
作業場所をホームディレクトリの下にまとめる。
例として \texttt{\textasciitilde{}/workspace} を作り，
その中にこのリポジトリや提出用リポジトリを置く。

\begin{lstlisting}[style=codecell]
mkdir -p ~/workspace
cd ~/workspace
git clone git@github.com:ykinolab-tokai/signal-ml-training.git
\end{lstlisting}

すでに同じ場所へ取得済みの場合は \texttt{git clone} を省略する。リポジトリを取得したら，まず次を確認する。

\begin{lstlisting}[style=codecell]
pwd
ls
cd signal-ml-training
ls
git status
\end{lstlisting}

\texttt{pwd} は現在地，\texttt{ls} は現在地のファイル，
\texttt{git status} は Git が認識している変更状態を
確認するために使う。

\section{Python 環境の構築}

このリポジトリは Python 3.12 系を標準にする。
Python環境の管理には \texttt{uv} を用いる．

\begin{lstlisting}[style=codecell]
curl -LsSf https://astral.sh/uv/install.sh | sh
\end{lstlisting}

インストール末尾に表示される PATH の案内に従い，
ターミナルを開き直すか，案内された \texttt{source} コマンドを実行する。
次のコマンドでバージョンが表示されることを確認してから先へ進む。

\begin{lstlisting}[style=codecell]
uv --version
\end{lstlisting}

リポジトリルートで次を実行すると，
\texttt{pyproject.toml} と \texttt{uv.lock} に従い
Python 3.12 環境と \texttt{.venv} が用意される。
\texttt{pyproject.toml} は必要なパッケージの条件，\texttt{uv.lock} は解決済みのバージョンを記録する。
\texttt{--locked} はlockfileを書き換えず，不整合があれば停止する指定である。
取得前の空のディレクトリで実行せず，教材リポジトリのルートへ移動してから実行する。

\begin{lstlisting}[style=codecell]
uv python install 3.12
uv sync --locked
source .venv/bin/activate
python --version
which python
\end{lstlisting}

\texttt{python --version} が 3.12 系であり，
\texttt{which python} が \texttt{.venv} 配下を指していれば，
授業用の環境に入っている。

\section{VS Code からこのリポジトリを開く}

このリポジトリを VS Code で開くには，
Ubuntu（WSL）または Mac のターミナルで次を実行する。

\begin{lstlisting}[style=codecell]
cd ~/workspace/signal-ml-training
code .
\end{lstlisting}

VS Code の Explorer に \texttt{pyproject.toml} と \texttt{uv.lock} が見えていることを確認する。

WSL の場合は，VS Code の左下やウィンドウ名に
\texttt{WSL: Ubuntu-24.04} のように表示されていることを確認する。
このウィンドウのターミナルも Ubuntu 側で動作する。

ターミナルからプログラムを実行する場合は，
前節で準備した \texttt{uv} を使ってリポジトリの環境で実行できる。
VS Code のターミナルでも，通常の Ubuntu や Mac のターミナルでも同じ操作でよい。
次の例は，「最初の動作確認」のサンプルファイルを保存した後に実行する。

\begin{lstlisting}[style=codecell]
cd ~/workspace/signal-ml-training
uv run --locked python exercises/exc01_01.py
\end{lstlisting}

\texttt{uv run --locked} はlockfileを更新せずにリポジトリの環境を確認・同期してから実行するため，
事前に \texttt{source .venv/bin/activate} を実行する必要はない。
一方，\texttt{python exercises/exc01\_01.py} と直接実行する場合は，
そのターミナルで \texttt{.venv} が有効になっていることを先に確認する。
新しいターミナルで \texttt{python} を直接使うときは，その都度 \texttt{.venv} を有効にする。
詳しくは \href{https://docs.astral.sh/uv/guides/projects/}{uv のプロジェクト操作} を参照する。

\section{VS Code の実行・デバッグ機能で \texttt{.venv} を使う（任意）}

以下は，VS Code の実行ボタンやデバッグ機能から，
リポジトリの \texttt{.venv} にある Python を使いたい場合の任意の設定である。
リポジトリを VS Code で開いて編集するだけの場合や，ターミナルで \texttt{uv run} を使う場合には，
この設定は必要ない。「最初の動作確認」へ進んでよい。
授業用の Python 環境は，どの実行方法でも「Python 環境の構築」で説明した \texttt{uv} で管理する。

この設定を行う場合は，まずリポジトリのルートで次を実行し，
\texttt{pyproject.toml} と \texttt{uv.lock} に従って \texttt{.venv} を準備する。

\begin{lstlisting}[style=codecell]
cd ~/workspace/signal-ml-training
uv sync --locked
\end{lstlisting}

VS Code の Python 実行・デバッグ機能を使うには，
Microsoft の Python 拡張機能が必要である。
入っていない場合は，VS Code の拡張機能画面で \texttt{Python} を検索し，
Microsoft が提供しているものをインストールする。
WSL の場合は，拡張機能画面で Ubuntu 側でも有効になっていることを確認し，
\texttt{Install in WSL: Ubuntu-24.04} と表示される場合はそのボタンでインストールする。

次に，このリポジトリで使う Python を明示的に選ぶ。

\begin{enumerate}
\item Windows では \texttt{Ctrl+Shift+P}，Mac では \texttt{Cmd+Shift+P} で Command Palette を開く。

\item \texttt{Python: Select Interpreter} を実行する。

\item このリポジトリ内の \texttt{.venv/bin/python} に対応する Python 3.12 を選ぶ。

\end{enumerate}

選択するパスの例は次のとおりである。
\begin{itemize}
\item WSL：\texttt{/home/yourname/workspace/signal-ml-training/.venv/bin/python}
\item Mac：\texttt{/Users/yourname/workspace/signal-ml-training/.venv/bin/python}
\end{itemize}
\texttt{yourname} は自分の user name に読み替える。
候補に \texttt{.venv} が見つからない場合は，リポジトリのルートで \texttt{uv sync --locked} が成功したことを確認し，
Command Palette の \texttt{Developer: Reload Window} でウィンドウを再読み込みしてから選び直す。

選択後，既存のターミナルをゴミ箱ボタンで終了し，
メニューの \texttt{Terminal} → \texttt{New Terminal} から新しいターミナルを開く。
次を実行して，そのターミナルの現在地と Python を確認する。

\begin{lstlisting}[style=codecell]
cd ~/workspace/signal-ml-training
pwd
which python
python --version
\end{lstlisting}

\texttt{pwd} がリポジトリのルート，\texttt{which python} がこのリポジトリ内の \texttt{.venv/bin/python}，
\texttt{python --version} が 3.12 系を示すことを確認する。
新しいターミナルで仮想環境が自動的に有効にならない場合は，
リポジトリのルートで \texttt{source .venv/bin/activate} を実行し，もう一度確認する。

VS Code の実行ボタンで使われる Python も確認する。

次の 2 行をリポジトリ直下の \texttt{interpreter\_check.py} として保存する。

\begin{lstlisting}[style=codecell]
import sys
print(sys.executable)
\end{lstlisting}

このファイルをエディタで開いた状態で，右上の \texttt{Run Python File in Terminal} を押す。
同じ操作は，エディタ内を右クリックし，\texttt{Run} → \texttt{Python File in Terminal} からも選べる。
表示されるパスがこのリポジトリ内の \texttt{.venv/bin/python} であることを確認する。
異なる場合は \texttt{Python: Select Interpreter} でこのリポジトリの \texttt{.venv} を選び直す。

\texttt{Run Python File in Terminal} は，VS Code で選択した Python を使ってファイルを実行する。
デバッグ機能も，実行環境を個別に指定していなければ，この選択を使う。
教材を更新して依存パッケージが変わった場合は，実行前にリポジトリのルートで \texttt{uv sync --locked} を行う。
詳しくは \href{https://code.visualstudio.com/docs/python/run}{VS Code の Python 実行手順} を参照する。

\section{教材リポジトリと作業リポジトリの使い分け}\label{ux6559ux6750repoux3068ux4f5cux696drepoux306eux4f7fux3044ux5206ux3051}}

教材リポジトリは教材・見本・共通の依存関係を読む場所で，第1回の動作確認もここで行う。
第2回以降の解答は自分の作業リポジトリ（提出リポジトリ）へ保存する。
\href{https://github.com/ykinolab-tokai/signal-ml-training/blob/main/handouts/01-environment-and-workflow.md\#自分用リポジトリの作成}{第1回の作成手順}に従い，
作業用テンプレートから \texttt{ykinolab-tokai} 所有の非公開
\texttt{signal-ml-work-\textless{}GitHubユーザー名\textgreater{}}
を作成する。 作成したリポジトリのREADMEに従って
\texttt{\textasciitilde{}/workspace/signal-ml-work} にcloneする。
取得済みならそのフォルダを開き，二重にcloneしない。 教材リポジトリは
\texttt{\textasciitilde{}/workspace/signal-ml-training}，作業リポジトリは
\texttt{\textasciitilde{}/workspace/signal-ml-work} に並ぶ。

第2回以降と補足の課題の相対パスは，特記がなければ作業リポジトリのルートを基準とする。

\begin{itemize}
\item
  コードの標準は
  \texttt{exercise/excXX\_YY.py}（回番号・問題番号は2桁）。各回が
  \texttt{scripts/}
  以下などを指定した場合はその指定を優先する。フォルダなしのファイル名だけを指定した場合は作業リポジトリのルートに置く。
\item
  図・音声・数値結果の標準は \texttt{outputs/}
  以下。説明はコードコメントまたは既存の結果ファイルに残し，別レポートは必要な課題が明示した場合だけ作る。同じ内容を転記しない。
\item
  \texttt{data/cat.png} や \texttt{data/piano.wav}
  を使う場合は，教材リポジトリの同名ファイルを作業リポジトリの \texttt{data/}
  へコピーする。
\end{itemize}

環境の初回準備は本章の前半に従う。教材更新後の依存関係の同期は教材リポジトリで行う。

\begin{lstlisting}[style=codecell]
cd ~/workspace/signal-ml-training
uv sync --locked
\end{lstlisting}

演習時は作業リポジトリへ移動し，教材側の仮想環境を有効にする。

\begin{lstlisting}[style=codecell]
cd ~/workspace/signal-ml-work
source ../signal-ml-training/.venv/bin/activate
pwd
python --version
which python
\end{lstlisting}

\texttt{pwd} が作業リポジトリ，\texttt{which\ python} が教材側の
\texttt{.venv/bin/python} を指すことを確認する。 例えば第2回第1問は
\texttt{python\ exercise/exc02\_01.py} で実行する。
配置を変えた場合は実際のパスへ読み替える。\texttt{.venv}
は作業リポジトリへコピーせず，毎回作り直さない。 保存前に
\texttt{Path(...).mkdir(parents=True,\ exist\_ok=True)}
などで出力ディレクトリを作る。 保存規則とPR練習後の通常作業への戻り方は
\href{https://github.com/ykinolab-tokai/signal-ml-training/blob/main/handouts/README.md\#作業場所と保存先}{共通手順}を参照する。

\section{うまく進まないとき}

\begin{itemize}
\item WSLのバージョンが2.4.10未満：PowerShellで \texttt{wsl --update} を実行し，Windows Terminalを開き直して \texttt{wsl --version} を再確認する。

\item \texttt{wsl -l -v} でUbuntuの \texttt{VERSION} が1：PowerShellで \texttt{wsl --set-version Ubuntu-24.04 2} を実行し，\texttt{wsl -l -v} で2になったことを確認する。

\item \texttt{code} や \texttt{uv} が見つからない：インストール完了時のPATH設定を確認してターミナルを開き直し，\texttt{code --version} または \texttt{uv --version} を再実行する。

\item \texttt{uv sync --locked} がプロジェクトを見つけられない：\texttt{pwd} と \texttt{ls} で教材リポジトリの \texttt{pyproject.toml} と \texttt{uv.lock} がある場所か確認する。

\item lockfileと設定の不整合で停止する：授業で指定された教材の版か確認し，担当者にエラーを伝える。自分だけ依存関係を変更しない。

\item Pythonのパスが \texttt{.venv} ではない：教材リポジトリで \texttt{source .venv/bin/activate} を実行し，\texttt{which python} と \texttt{python --version} を再確認する。

\item 画像が見つからない：実行時の現在地を \texttt{pwd} で確認する。サンプルはその現在地を基準に \texttt{outputs/setup\_check/sin.png} を作る。

\end{itemize}
