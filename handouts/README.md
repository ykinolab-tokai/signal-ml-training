# handouts 概要

このディレクトリには学生配布用 Markdown を置きます。各 handout は、学生がその回の概要をつかみ、演習に着手するための最低限の知識を得て、何をどこまで考えて実装・説明すべきかを一意に解釈できることを目的に書きます。詳細説明は `textbook/` や公式 docs に委ね、`handouts/` では学習目標、演習に必要な最小知識、課題仕様、確認項目、参照先を明示します。

## 構成

- `01-...md` から `28-...md`: 学生が取り組む順に並べた各回の配布資料
- `advanced/`: 第 25〜27 回で年度ごとに選ぶ発展テーマの候補資料
- 新規作成または大きな改訂では、[`../templates/session-template.md`](../templates/session-template.md) を使う。

## handout の共通方針

- 各回の handout は、`この回の目標`, `解説`, `演習`, `確認ポイント`, `詰まったときに見る資料` の 5 セクションだけで構成する。
- `この回の目標` には、その回で理解・説明・実装できるようになってほしいことを 2 から 4 項目で書く。
- `解説` には、演習に手を付けるために最低限必要な知識だけを書く。概念の定義、入力と出力の対応、今回使う式や API の意味、典型的な見落としを短く説明し、詳細な背景説明はここに入れない。
- `演習` は `基礎レベル` と `発展レベル` に分ける。`基礎レベル` は全員が迷わず着手できる必須課題、`発展レベル` は基礎の理解を使って追加の比較・解釈・設計判断を行う課題にする。
- 演習では「小さな例」「簡単な計算」「適宜変更」などの曖昧な表現は使わず、入力、制約、保存物、比較対象、確認すべき観点を明示する。
- ただし、演習を単なる転記課題にしない。配列の値や題材を固定してよいが、学生が結果の解釈、比較、設計上の選択理由、失敗時の切り分けのどれかを自分で考える問いを必ず含める。
- `基礎レベル` では、完了条件を固定しつつも、少なくとも 1 問は「なぜその結果になるか」「どこが入力と出力を決めているか」を説明させる。
- `発展レベル` では、比較条件や評価観点は handout 側で固定し、どの案を採るか、何を優先するか、どの差を重要とみなすかは学生に考えさせる。
- 図・音・中間結果が必要な回では、表示や再生だけで終えず、保存物と確認観点を `演習` または `確認ポイント` に明記する。
- `確認ポイント` には、学生が自己点検できる具体的な観点を書く。shape、値の傾向、保存物の有無、比較結果の説明有無など、手元で確認できる形にする。
- 詳細説明は `textbook/markdown/` や公式 docs に委ね、`詰まったときに見る資料` には優先度の高い資料だけを 2 件程度まで明記する。

## 作業場所と保存先

- **教材repo**（`signal-ml-training`）は，教材・見本・共通の依存関係を読む場所とする。第1回の環境確認サンプルだけは，このrepoの `exercises/` に保存する。
- **提出repo**（学生ごとの非公開のsubmission repo）は，第2回以降の解答を保存・提出する場所とする。URLと実際のフォルダ名は授業で指定されたものを使い，不明な場合は担当者に確認する。
- 第2〜13回の `scripts/`，`outputs/`，`data/` は，特記がない限り**提出repoのルートからの相対パス**である。コードは `scripts/sessionXX_名前.py`，説明と数値結果は `outputs/sessionXX/sessionXX_report.md`，図・音声は各回で指定した `outputs/` 以下へ保存する。
- 教材repoの `.venv` を利用する。第1回と同じ場所に教材repoを置いた場合，提出repoのルートで `source ~/workspace/signal-ml-training/.venv/bin/activate` を実行してから `python scripts/ファイル名.py` を使える。`.venv` を提出repoへコピーしたり，毎回作り直したりする必要はない。教材repoを別の場所に置いた場合はそのパスに読み替える。
- `data/cat.png` や `data/piano.wav` を使う回では，教材repoの同名ファイルを提出repoの `data/` へコピーする。入力ファイルと自分が生成した `outputs/` を区別する。
- 各回の出力ディレクトリは，保存前に `Path(...).mkdir(parents=True, exist_ok=True)` などで作る。実行時の現在地は提出repoのルートにそろえる。

## 演習の進め方

基礎レベルを必須の核とし，実行前の予測，実装，結果の確認を一組として扱う。
発展レベルは基礎を終えた後に選択する課題であり，全問の実施を前提にしない。問題数は各回の目標に合わせ，7問ずつには固定しない。
保存やレポート作成は各課題の完了条件であり，別の追加問題として数えない。
授業時間内に終わらなかった作業の扱い・提出期限は授業の指定に従う。

## 旧資料の吸収方針

- 以前の notebook 群と演習シートにあった具体課題は、現在の回構成に合わせて各 handout に再配置しています。
- 旧 `initial-training/<your_name>/chapterXX` 前提の提出先指定は採用せず、現在の repo と授業運営に合わせて書き換えています。
- B3 の通常提出は学生ごとの private な `submission repo` を前提とし、共通 repo は教材配布と見本コードの参照先として扱います。
- `pull request` は第14回の code walkthrough と repo 整理で体験しますが、毎週の通常提出では `edit -> commit -> push` を基本にします。

## 読み方

- 学生が取り組む順に、`01` から `28` までの回番号付き handout を使います。
- B3 向けの固定ブートキャンプでは `01` から `14` を使います。
- B4・M 向けの発展枠では `15` から `28` を使います。
- 第 25〜27 回は、画像・音響・共通基盤のうち年度ごとに 1 テーマだけを選び、3 回に分けて扱います。候補 handout は [`advanced/`](advanced/) から参照します。
- handout に書かれていない追加作業をその場で課すのではなく、必要なら handout 自体を書き換えてから配布します。
