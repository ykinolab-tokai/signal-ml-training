### 1. sounddevice を用いた音信号の再生と収録

コンピュータ上の音信号は，第7回で扱った離散時間信号として扱われる。
すなわち，音信号は，離散時間 $n$ における音の振幅（強さ）を表す信号 $x[n]$ と，サンプリング周波数 $F_s$ [Hz] の組で表される。
振幅値は整数や浮動小数点数で表されるが，浮動小数点数を用いる場合には $[-1, 1]$ の範囲で扱うことが多い。

音信号には，左右のスピーカー（やイヤホン）のそれぞれに対応する 2 つの振幅 $x_L[n]$，$x_R[n]$ を持たせる場合がある。
このような信号を **ステレオ信号 (stereo signal)**，または，2 チャネル信号という。
$x_L[n]$ や $x_R[n]$ のように，音信号を構成する振幅の系列の 1 つ 1 つを **チャネル (channel)** といい，その数をチャネル数という。
ステレオ信号に対して，1 つの振幅 $x[n]$ だけを持つ信号は **モノラル信号 (monaural signal)** という。
また，一般に，チャネル数が 2 以上の信号をまとめて **多チャネル信号 (multichannel signal)** という。

音の再生や収録など，スピーカーやマイクなどのデバイスを用いた処理のためのライブラリとして，`sounddevice` がある。
`sounddevice` は，音信号を NumPy 配列として扱う。
デバイスの操作は環境に依存するため，（特に WSL 上では）正常に実行できないことがある。
その場合は，第2節の方法で音を WAV ファイルに保存し，PC の音声プレーヤーで再生して聴く。
また，Linux で PortAudio（`libportaudio2`）が入っていない環境では，`import sounddevice` の時点で `OSError: PortAudio library not found` というエラーになる。
このため，`sounddevice` は冒頭の処理には含めず，再生や収録を行うスクリプトでだけ読み込む。

#### 音信号の再生

音信号を再生するには，`sounddevice.play` を用いる。
音信号の再生の完了を待つには，`sounddevice.wait` を用いる。
音を再生する際には，意図しない大きな音が出ないように，まずはコンピュータの設定で音量を小さめにしておくことをおすすめする。
問題がなければ音量を大きくすると良い。

```python
import sounddevice as sd

fs = 48000
duration = 3

# 440 Hz の正弦波を作って再生
t = np.linspace(0, duration, int(fs * duration), endpoint=False)
x = 0.2 * np.sin(2 * np.pi * 440 * t)

sd.play(x, fs)
sd.wait()
```

`np.linspace(0, duration, int(fs * duration), endpoint=False)` は，終点 `duration` を含めずに，間隔 $1/F_s$ で並ぶ時刻 $n/F_s$（$n = 0, 1, \ldots, 143999$）を作る。
これは，浮動小数点数の丸め誤差を除いて `np.arange(int(fs * duration)) / fs` と同じ値である。
`sd.play(x, fs)` は再生を始めるとすぐに次の行へ進むため，`sd.wait()` で再生の終了を待つ。
`sd.wait()` を書かずにスクリプトが終了すると，再生は途中で止まる。
第 2 引数には，音信号を作ったときのサンプリング周波数を渡す。
異なる値を渡すと，再生される音の長さと高さが変わる。

ライブラリを用いる場合には，公式ドキュメントを参照して，その仕様を理解することが重要である。
公式ドキュメントで `play` 関数の仕様を確認しよう。
今後も，新しいライブラリを使うときには，まずは公式ドキュメントを確認する習慣をつけると良い。

ドキュメントから分かる通り，`sounddevice` は多チャネル信号を `(num_samples, num_channels)` の形を持つ 2 次元の NumPy 配列として扱う。
よって，多チャネル信号は，次のように作成・再生できる。

```python
x_left = 0.2 * np.sin(2 * np.pi * 440 * t)
x_right = 0.2 * np.sin(2 * np.pi * 880 * t)
x_stereo = np.stack([x_left, x_right], axis=-1)
print(x_stereo.shape)  # (144000, 2)

sd.play(x_stereo, fs)
sd.wait()
```

`np.stack([x_left, x_right], axis=-1)` は，形 `(144000,)` の 2 つの配列を新しい最後の軸に並べ，形 `(144000, 2)` の配列を作る。
`axis=0` で並べると形 `(2, 144000)` となり，2 サンプルで 144000 チャネルの信号とみなされてしまうので注意する。
`numpy.stack` 等は初めて見る人もいるかもしれないが，これも NumPy の [公式ドキュメント](https://numpy.org/doc/stable/reference/generated/numpy.stack.html) を見れば用途や仕様が分かるので確認しよう。

#### 音信号の収録

音信号を収録するには，`sounddevice.rec` を用いる。
この関数は，録音するサンプル数，サンプリング周波数，チャネル数などを指定して，録音した音信号を NumPy 配列として返す。
多チャネル信号の収録には，それに対応したマイクが必要になるため注意しよう。

```python
fs = 48000          # サンプリング周波数 [Hz]
duration = 5        # 録音時間 [秒]
channels = 1        # 1: mono, 2: stereo

print("録音開始")
audio = sd.rec(
    int(duration * fs),
    samplerate=fs,
    channels=channels,
    dtype="float32",
)
sd.wait()           # 録音終了まで待つ
print("録音終了")
```

`sd.rec` も録音を始めるとすぐに次の行へ進み，返された配列 `audio` には録音中のデータが順に書き込まれる。
このため，`sd.wait()` で録音の終了を待ってから `audio` を使う。
`audio` は，`channels=1` の場合でも形 `(サンプル数, チャネル数)` の 2 次元配列であり，この例では形 `(240000, 1)` になる。
1 次元の信号として扱うには，`audio[:, 0]` のように 1 つのチャネルを取り出す。
録音した音は，第2節の `sf.write` でファイルに保存できる。

### 2. soundfile を用いた音信号の読み書き

音信号をファイルとして記録したり，ファイルとして保存されている音信号を読み込んだりするには，`soundfile` が便利である。
`soundfile` も，`sounddevice` と同様に，音信号を NumPy 配列として扱う。

#### 音の保存

音信号の保存には，`soundfile.write` を利用する。
音信号のためのファイル形式には，WAV，FLAC，MP3 などがある。
ファイル形式によっては，ファイルサイズを小さくするために，音信号の情報を削減したうえで圧縮符号化することがある。
これを **非可逆圧縮 (lossy compression)** といい，MP3 はその代表例である。
FLAC は，情報を失わずに圧縮する **可逆圧縮 (lossless compression)** の形式である。
研究用途では，音信号の内容をできるだけ忠実に保存するために，非可逆圧縮を行わない WAV などのファイル形式を選ぶことが多い。

```python
fs = 22050
t = np.arange(int(0.5 * fs)) / fs                # 0.5 秒分の時刻
left = 0.5 * np.sin(2 * np.pi * 440 * t)
right = 0.25 * np.sin(2 * np.pi * 660 * t)
stereo = np.stack([left, right], axis=-1)
print(stereo.shape)  # (11025, 2)

wav_path = figure_dir / "session09_example_stereo.wav"
sf.write(wav_path, stereo, fs)
print(sf.info(wav_path).subtype)  # PCM_16
```

`sf.write(ファイル名, 信号, サンプリング周波数)` は，信号をファイルに保存する。
ファイル形式は拡張子（`.wav`）から決まり，多チャネル信号は `sounddevice` と同じく形 `(サンプル数, チャネル数)` の配列で渡す。
サンプリング周波数はファイルに記録されるが，配列には含まれないため，必ず一緒に渡す。
`sf.info` はファイルの情報（サンプリング周波数，チャネル数，長さなど）を返し，その `subtype` はサンプルの保存形式を表す。
WAV の既定の保存形式 `PCM_16` は，各サンプルを 16 bit の整数に量子化（第7回）して保存する。
このとき，絶対値が 1 を超える値は，16 bit の整数で表せる最大値または最小値に置き換えられる。
この置き換えを **クリッピング (clipping)** という。
浮動小数点数のまま保存したい場合は，`sf.write(..., subtype="FLOAT")` を指定する。

#### 音の読み込み

ファイルに保存されている音信号を読み込むには，`soundfile.read` を利用する。
この関数は，音信号を NumPy 配列として返すとともに，そのサンプリング周波数も返す。

```python
data, fs_read = sf.read(wav_path)
print(data.shape, data.dtype, fs_read)  # (11025, 2) float64 22050
print(len(data) / fs_read)              # 0.5
mono = data[:, 0]                       # 左チャネルだけを取り出す
print(np.max(np.abs(mono - left)))      # 約 3.05e-05
```

`sf.read` は，既定では値を `float64` 型の配列として返し，`PCM_16` のような整数の保存形式の値は $[-1, 1]$ の範囲に換算される。
`dtype="float32"` や `dtype="int16"` を指定すると，その型で読み込める。
配列の形は，モノラル信号では `(サンプル数,)` の 1 次元，多チャネル信号では `(サンプル数, チャネル数)` の 2 次元になる。
ファイルによってチャネル数が異なるため，読み込んだら `data.ndim` や `data.shape` を確認し，必要なら `data[:, 0]` のように 1 つのチャネルを取り出す。
信号の長さ [s] は，サンプル数をサンプリング周波数で割って求める。
最後の行は，保存前の左チャネル `left` と，読み込んだ左チャネル `mono` の差の絶対値の最大値である。
16 bit の整数で表せる値の間隔は $2/2^{16} = 2^{-15} \approx 3.05\times10^{-5}$ であり，保存と読み込みで生じた誤差はこの間隔以下になっている。

### 3. フーリエ変換によるスペクトルの可視化

#### 振幅スペクトルの計算

波形 $x[n]$ は時間方向の変化を表す。
一方，第8回で扱った DFT を用いると，信号にどの周波数成分がどれだけ含まれるかを確認できる。
音信号は実数値であり，その DFT は対称性 $X[N-k] = \overline{X[k]}$（第8回）を持つ。
このため，$k = 0, 1, \ldots, \lfloor N/2 \rfloor$ の値だけを返す [`numpy.fft.rfft`](https://numpy.org/doc/stable/reference/generated/numpy.fft.rfft.html) を使うと，冗長な計算を省いてスペクトルを計算できる。
$\lfloor a \rfloor$ は，$a$ 以下の最大の整数を表す。
$N$ 点の DFT の $k$ 番目の要素を **周波数ビン (frequency bin)** といい，$k$ 番目の周波数ビンは周波数 $kF_s/N$ [Hz] に対応する。
各周波数ビンがどの周波数に対応するかは，[`numpy.fft.rfftfreq`](https://numpy.org/doc/stable/reference/generated/numpy.fft.rfftfreq.html) で計算できる。

周期 $T$ の周期信号は，定数と，周波数 $1/T$ の整数倍の正弦波の和で表せる。
周波数 $f_0 = 1/T$ を **基本周波数 (fundamental frequency)** といい，その整数倍の周波数 $2f_0, 3f_0, \ldots$ の成分を **倍音 (harmonic)** という。
楽器の音や声の母音は周期信号に近く，スペクトルには基本周波数とその倍音の位置にピークが並ぶ。
次の例では，基本周波数 250 Hz で，2 倍音と 3 倍音を含む音の振幅スペクトルを計算する。

```python
fs = 8000
t = np.arange(fs) / fs                       # 1 秒分の時刻
f0 = 250
x = (0.4 * np.sin(2 * np.pi * f0 * t)
     + 0.2 * np.sin(2 * np.pi * 2 * f0 * t)
     + 0.1 * np.sin(2 * np.pi * 3 * f0 * t))

X = np.fft.rfft(x)
freq = np.fft.rfftfreq(len(x), d=1 / fs)
amp = np.abs(X)
print(X.shape, freq[1] - freq[0], freq[-1])  # (4001,) 1.0 4000.0
print(freq[amp > 0.01 * amp.max()])          # [250. 500. 750.]
k = np.array([250, 500, 750]) * len(x) // fs
print(amp[k] / (len(x) / 2))                 # [0.4 0.2 0.1]
```

`np.fft.rfft` は，長さ $N = 8000$ の実数の配列から，長さ $N/2 + 1 = 4001$ の複素数の配列を返す。
`np.fft.rfftfreq(N, d=1 / fs)` は，各周波数ビンに対応する周波数 [Hz] を返す。
引数 `d` はサンプリング周波数ではなくサンプリング周期 $1/F_s$ であり，`d=fs` と書くと周波数の値が誤る点に注意する。
周波数ビンの間隔は $F_s/N = 1$ Hz であり，最後の要素はナイキスト周波数 $F_s/2 = 4000$ Hz（第7回）に対応する。
振幅が最大値の 1% を超える周波数ビンは 250 Hz，500 Hz，750 Hz の 3 つであり，基本周波数と 2 つの倍音の位置にピークがある。
`k` は，周波数 [Hz] を周波数ビンの番号 $fN/F_s$ に換算したものである。
振幅 $A$ の正弦波の周波数が周波数ビンにちょうど一致する場合，その周波数ビンの DFT の絶対値は $AN/2$ になる。
このため，$|X[k]|$ を $N/2$ で割ると，各成分の振幅 0.4，0.2，0.1 が得られる。

#### デシベル表示

音のスペクトルでは，大きな成分と小さな成分の振幅の比が非常に大きいことが多い。
そこで，振幅 $A$ を，基準の値 $A_{\mathrm{ref}}$ との比の対数を使った **デシベル (decibel, dB)** の値 $20\log_{10}(A/A_{\mathrm{ref}})$ で表すことが多い。
パワー（振幅の 2 乗）$P$ の場合は，$10\log_{10}(P/P_{\mathrm{ref}})$ を用いる。
$P = A^2$ なので，振幅とパワーのどちらから計算しても同じ dB の値になる。
振幅が $1/2$ 倍になると約 $6$ dB，$1/10$ 倍になると $20$ dB 小さくなる。

```python
amp_db = 20 * np.log10(np.maximum(amp, 1e-12) / amp.max())
print(np.round(amp_db[k], 2))  # [  0.    -6.02 -12.04]

fig, ax = plt.subplots(figsize=(8, 3))
ax.plot(freq, amp_db, linewidth=0.8)
ax.set_xlim(0, 2000)
ax.set_ylim(-80, 5)
ax.set_xlabel("frequency [Hz]")
ax.set_ylabel("magnitude [dB]")
ax.grid(True)
fig.tight_layout()
fig.savefig(figure_dir / "session09_example_spectrum.png")
plt.show()
plt.close(fig)
```

ここでは，振幅の最大値を基準 $A_{\mathrm{ref}}$ とし，最大の成分が 0 dB になるようにしている。
振幅の比 $1 : 0.5 : 0.25$ は，0 dB，$-6.02$ dB，$-12.04$ dB に対応する。
`np.maximum(amp, 1e-12)` は，振幅が 0 の要素で $\log_{10} 0 = -\infty$ になるのを防ぐための処理である。
この例では，ピーク以外の周波数ビンの振幅はほぼ 0 であり，その dB の値は非常に小さくなるため，`ax.set_ylim` で表示範囲を $-80$ dB 以上に限定している。

### 4. 短時間フーリエ変換

音声や音楽のように時間とともに内容が変化する信号では，信号の周波数成分と時間変化の両方を解析することが重要である。
しかし，信号全体に対するフーリエ変換では，信号に含まれる周波数成分は分かるが，各成分がいつ現れたかは分からない。
この問題を解決するために，信号を短い時間区間（**フレーム (frame)**）に分割して，各フレームに対してフーリエ変換を行う方法がある。
この方法を **短時間フーリエ変換 (short-time Fourier transform, STFT)** という。

#### 窓関数 (window function)

第8回で扱った **窓関数 (window function)** は，STFT では信号からフレームを切り出すために使う。
最も単純な窓関数として，次式で与えられる **矩形窓 (rectangular window)** がある。

$$
w[n] = \begin{cases}
1 & 0 \leq n < N \\
0 & \text{otherwise}
\end{cases}
$$

ここで，$N$ は切り出したいフレームの長さを表すパラメータであり，**フレーム長 (frame length)** や **窓長 (window length)** と呼ばれる。
信号 $x$ から $H$ 点間隔で長さ $N$ のフレームを切り出す操作は，次式で与えられる。

$$
x_m[n] = x[n + mH] w[n], \quad m \in \mathbb{Z}
$$

$H$ は，**ホップ長 (hop length)** や **フレームシフト (frame shift)** とも呼ばれるパラメータである。
$H < N$ のとき，隣り合うフレームは重複する区間を持つ。
このとき，$N - H$ はフレームが重なる幅を表し，**オーバーラップ (overlap)** 幅などと呼ばれる。
ホップ長は，窓長に対する割合で与えることも多い。
$H = N/4$ や $H = N/2$ などがよく使われる。

矩形窓以外にも様々な窓関数があり，代表的なものに **ハン窓 (Hann window)** と **ハミング窓 (Hamming window)** がある。
ハン窓は次式で与えられる。

$$
w[n] = \begin{cases}
0.5 \left(1 - \cos\left(\dfrac{2\pi n}{N - 1}\right)\right) & 0 \leq n < N \\
0 & \text{otherwise}
\end{cases}
$$

ハミング窓は次式で与えられる。

$$
w[n] = \begin{cases}
0.54 - 0.46 \cos\left(\dfrac{2\pi n}{N - 1}\right) & 0 \leq n < N \\
0 & \text{otherwise}
\end{cases}
$$

どちらの窓も中央付近で最大になり（$N$ が奇数なら中央の $n = (N-1)/2$ で 1），両端に近づくほど小さくなる。
ハン窓は両端で 0 になるが，ハミング窓は両端で 0.08 になる。
NumPy の `np.hanning(N)` と `np.hamming(N)` は，これらの式の窓を返す。
一方，`librosa.stft` で `window="hann"` を指定したときに使われるハン窓（`librosa.filters.get_window("hann", N)` で得られる）は，式の分母 $N - 1$ を $N$ に置き換えたものである。

```python
print(np.round(np.hanning(8), 3))
print(np.round(librosa.filters.get_window("hann", 8), 3))
```

```text
[0.    0.188 0.611 0.95  0.95  0.611 0.188 0.   ]
[0.    0.146 0.5   0.854 1.    0.854 0.5   0.146]
```

`np.hanning(8)` は左右対称で両端が 0 であるのに対し，librosa のハン窓は $n = 0$ でだけ 0 になり，$n = 4$ で最大値 1 をとる。
librosa のハン窓は，周期 $N$ で繰り返したときに滑らかにつながるように作られた窓である。
`librosa.filters.get_window("hamming", N)` のハミング窓も，同様に分母を $N$ に置き換えたものである。

#### スペクトル漏れ

窓関数の形は，切り出したフレームのスペクトルに影響する。
第8回で扱ったように，信号を長さ $N$ で切り出して DFT を計算すると，周波数が周波数ビンに一致しない成分は，そのピークの周りの多くの周波数ビンにも広がって現れる。
この現象を **スペクトル漏れ (spectral leakage)** という。
DFT は，切り出した $N$ 点が周期的に繰り返す信号とみなして計算する。
このため，切り出した区間の始まりと終わりで波形がなめらかにつながらないと，そのつなぎ目の急な変化を表すために多くの周波数成分が必要になる。
次の例では，周波数が周波数ビン 10 と 11 のちょうど中間にある正弦波を 64 点で切り出し，矩形窓とハン窓のそれぞれについて，周波数ビン 20 の値をピークと比べる。

```python
N = 64
n = np.arange(N)
tone = np.sin(2 * np.pi * 10.5 * n / N)  # 周波数ビン 10 と 11 の中間の周波数
for name, w in [("rectangular", np.ones(N)), ("hann", np.hanning(N))]:
    a = np.abs(np.fft.rfft(tone * w))
    print(name, round(20 * np.log10(a[20] / a.max()), 1))
```

```text
rectangular -26.7
hann -67.7
```

矩形窓では，ピークから約 10 ビン離れた周波数ビン 20 にも，ピークより 26.7 dB 小さいだけの値が現れている。
ハン窓では，切り出した信号が両端に向かってなめらかに 0 に近づくため，周波数ビン 20 の値はピークより 67.7 dB 小さい。
このように，ハン窓などの窓関数を掛けると，スペクトル漏れを小さくできる。
ただし，ハン窓を掛けると，ピーク自体の幅は矩形窓より広がる。
第3節の例ではすべての成分の周波数が周波数ビンに一致していたため，窓関数を掛けなくても各成分が 1 本のピークになった。
実際の音では成分の周波数が周波数ビンに一致するとは限らないため，振幅スペクトルを求める前にハン窓などを掛けることが多い。

#### STFT の定義

ホップ長を $H$，窓関数を $w[n]$ としたとき，STFT は $x_m[n]$ の DFT を各 $m$ について計算することで得られる。
すなわち，

$$
X[k, m] = \sum_{n=0}^{N-1} x_m[n] e^{-j 2\pi kn / N} = \sum_{n=0}^{N-1} x[n + mH] w[n] e^{-j 2\pi kn / N}
$$

で与えられる。
ここで，$k$ は周波数ビンの番号，$m$ はフレームの番号を表す。
STFT における DFT の点数は，上式の通りフレーム長 $N$ と一致させることが多い。
周波数ビン $k$ は周波数 $kF_s/N$ [Hz] に対応し，フレーム $m$ は時刻 $mH/F_s$ [s] から始まる長さ $N/F_s$ [s] の区間に対応する。
したがって，周波数ビンの間隔は $F_s/N$ [Hz]，隣り合うフレームの時間間隔は $H/F_s$ [s] である。
周波数方向にどれだけ近い成分を区別できるかを **周波数分解能 (frequency resolution)**（第8回），時間方向にどれだけ近い変化を区別できるかを **時間分解能 (time resolution)** という。
どちらもフレーム長 $N$ によって変わる。

STFT によって得られる $X[k, m]$ の絶対値 $|X[k, m]|$ やその 2 乗 $|X[k, m]|^2$ は，**スペクトログラム (spectrogram)** と呼ばれる（文献によって指す対象が異なるので注意）。
2 乗した $|X[k, m]|^2$ を，特にパワースペクトログラムと呼ぶこともある。

#### librosa による STFT の計算

Python を用いた STFT の計算には，`librosa.stft` を用いることができる。
次の例では，最初の 0.5 秒が 1000 Hz，残りの 0.5 秒が 2500 Hz の正弦波からなる信号の STFT を計算する。

```python
fs = 8000
t = np.arange(fs) / fs                     # 1 秒分の時刻
y = np.where(t < 0.5, 0.5 * np.sin(2 * np.pi * 1000 * t), 0.5 * np.sin(2 * np.pi * 2500 * t))

n_fft = 256
hop_length = 64
D = librosa.stft(y, n_fft=n_fft, hop_length=hop_length, window="hann")
print(D.shape, D.dtype)  # (129, 126) complex128

times = librosa.frames_to_time(np.arange(D.shape[1]), sr=fs, hop_length=hop_length)
freqs = librosa.fft_frequencies(sr=fs, n_fft=n_fft)
for m in [31, 94]:
    print(times[m], freqs[np.argmax(np.abs(D[:, m]))])
```

```text
0.248 1000.0
0.752 2500.0
```

`np.where(条件, a, b)` は，条件が真の要素では `a`，偽の要素では `b` の値をとる配列を返す。
`librosa.stft` の `n_fft` がフレーム長 $N$（DFT の点数），`hop_length` がホップ長 $H$，`window` が窓関数である。
`hop_length` を省略すると `n_fft // 4` が，`n_fft` を省略すると 2048 が使われるため，条件を比べるときは明示する。
結果 `D` は形 `(周波数ビンの数, フレーム数)` の複素数の配列であり，`np.fft.rfft` と同様に，周波数方向には $N/2 + 1 = 129$ 個の値だけが返る。

`librosa.stft` は，既定（`center=True`）では，信号の両端に $N/2$ 個ずつ 0 を補ってからフレームに分割する。
このため，フレーム $m$ は元の信号の $mH - N/2 \le n < mH + N/2$ の区間を切り出したものになり，その区間の中心の時刻は $mH/F_s$ [s] である。
長さ $T$ サンプルの信号から得られるフレーム数は $\lfloor T/H \rfloor + 1$ であり，この例では $\lfloor 8000/64 \rfloor + 1 = 126$ となる。
`librosa.frames_to_time` は各フレームの中心の時刻 [s] を，`librosa.fft_frequencies` は各周波数ビンの周波数 [Hz] を返す。
時刻 0.248 s のフレームでは 1000 Hz，時刻 0.752 s のフレームでは 2500 Hz の周波数ビンで振幅が最大になっており，各成分が現れた時刻が分かる。

```python
D_db = librosa.amplitude_to_db(np.abs(D), ref=np.max)
print(D_db.max(), D_db.min())  # 0.0 -80.0

fig, ax = plt.subplots(figsize=(8, 4))
img = librosa.display.specshow(D_db, sr=fs, hop_length=hop_length, x_axis="time", y_axis="hz", ax=ax)
fig.colorbar(img, ax=ax, format="%+2.0f dB")
fig.tight_layout()
fig.savefig(figure_dir / "session09_example_stft.png")
plt.show()
plt.close(fig)
```

音信号に含まれる高い周波数の成分は低い周波数の成分と比べて小さいことが多いため，スペクトログラムも dB で表示することが多い。
`librosa.amplitude_to_db(S, ref=np.max)` は，振幅 $S$ を，その最大値を基準とした dB の値 $20\log_{10}(S/\max S)$ に変換する。
既定の `top_db=80` により，最大値より 80 dB 以上小さい値は $-80$ dB に置き換えられる。
`librosa.display.specshow` は，2 次元配列の値を色で表した図を描く関数である。
`sr` と `hop_length` を渡すと，`x_axis="time"` で横軸を時刻 [s]，`y_axis="hz"` で縦軸を周波数 [Hz] として目盛りを付ける。
`sr` や `hop_length` を渡し忘れると，既定値（`sr=22050`，`hop_length=512`）で目盛りが付けられ，軸の値が誤る。
`specshow` の戻り値を `fig.colorbar` に渡すと，色と dB の値の対応を表すカラーバーが表示される。
図では，0.5 秒を境に，横線の位置が 1000 Hz から 2500 Hz に変わる。
0.5 秒付近と信号の両端では縦に広がる成分が現れるが，これは波形が急に変わる部分を含むフレームで，その変化を表すために多くの周波数成分が必要になるためである。

#### メルスペクトログラム

スペクトログラムは，線形（等間隔）な周波数軸を持つ時間周波数表現である。
一方，人間の聴覚は，低い周波数の違いには敏感で，高い周波数の違いには鈍感という，周波数に関して非線形な性質を持つ。
**メル尺度 (mel scale)** は，このような知覚特性を加味した周波数尺度である。
周波数 $F$ [Hz] からメル周波数 $M$ への変換には，次式がよく用いられる。

$$
M = 2595 \log_{10}\left(1 + \frac{F}{700}\right)
$$

この式の値は，$F$ が 700 Hz より十分小さい範囲ではほぼ $F$ に比例し，十分大きい範囲ではほぼ $\log F$ に比例して増える。
時間とメル周波数を軸とするスペクトログラムを **メルスペクトログラム (mel spectrogram)** という。
メルスペクトログラムは，音声認識や音響イベント認識などの入力特徴量としてよく使われる。

メルスペクトログラムの計算には，`librosa.feature.melspectrogram` を用いることができる。
この関数は，パワースペクトログラム $|X[k, m]|^2$ を計算した後，メル尺度で等間隔に並べた `n_mels` 個の三角形のフィルタで，周波数方向の値を重み付きで足し合わせる。

```python
mel = librosa.feature.melspectrogram(y=y, sr=fs, n_fft=n_fft, hop_length=hop_length, n_mels=40, power=2.0)
mel_db = librosa.power_to_db(mel, ref=np.max)
print(mel.shape)  # (40, 126)

fig, ax = plt.subplots(figsize=(8, 4))
img = librosa.display.specshow(mel_db, sr=fs, hop_length=hop_length, x_axis="time", y_axis="mel", ax=ax)
fig.colorbar(img, ax=ax, format="%+2.0f dB")
fig.tight_layout()
fig.savefig(figure_dir / "session09_example_mel.png")
plt.show()
plt.close(fig)
```

結果の形は `(n_mels, フレーム数)` であり，フレーム数は `librosa.stft` と同じである。
`power=2.0` はパワースペクトログラムから計算することを表すため，dB への変換には，パワー用の `librosa.power_to_db`（$10\log_{10}$）を使う。
振幅用の `librosa.amplitude_to_db`（$20\log_{10}$）を使うと，dB の値が 2 倍になってしまう。
`y_axis="mel"` を指定すると，縦軸がメル尺度の間隔で描かれ，目盛りには対応する周波数 [Hz] が表示される。
メル尺度で等間隔に並んだフィルタは，Hz で見ると高い周波数ほど広い範囲をまとめるため，高い周波数ほど粗く表される。

ただし，librosa の既定のメル尺度は上の式とは異なり，1000 Hz 以下では周波数に比例し，1000 Hz 以上では周波数の対数の 1 次式で表される別の定義（Slaney の定義）である。
各フィルタの重みの正規化（`norm="slaney"`）も既定で行われる。
上の式と同じメル尺度を使うには，`htk=True` を指定する。

```python
print(2595 * np.log10(1 + 1000 / 700))      # 約 999.99
print(librosa.hz_to_mel(1000.0, htk=True))  # 約 999.99
print(librosa.hz_to_mel(1000.0))            # 約 15.0
```

`librosa.hz_to_mel` は，周波数をメル周波数に変換する関数である。
`htk=True` を指定すると上の式と同じ値を返すが，省略すると別の定義の値（1000 Hz で約 15）を返す。
メル周波数の値を式と比べるときは，どちらの定義を使っているかを確認する。

#### 逆短時間フーリエ変換

STFT の結果から元の信号を求める変換を **逆短時間フーリエ変換 (inverse short-time Fourier transform, ISTFT)** という。
各フレームの $X[k, m]$ を逆 DFT（第8回）すると，窓を掛けたフレーム $x[n + mH]w[n]$ が得られる。
ISTFT は，これらのフレームを $H$ ずつずらして足し合わせ，重なった窓関数の影響を補正して元の信号を求める。
librosa では，`librosa.istft` で計算できる。

```python
y_rec = librosa.istft(D, n_fft=n_fft, hop_length=hop_length, window="hann", length=len(y))
print(y_rec.shape)                # (8000,)
print(np.max(np.abs(y - y_rec)))  # 約 2.8e-16
```

`librosa.istft` には，STFT と同じ `n_fft`，`hop_length`，`window` を指定する。
`length=len(y)` は，結果の長さを元の信号にそろえる指定である。
この例では，元の信号との差は浮動小数点数の丸め誤差程度であり，信号が元に戻っている。
ただし，窓関数とホップ長の組み合わせによっては，元の信号に戻らない場合もある。

4. ISTFT で元の信号を完全に再構成するための条件を導き，別の窓関数とホップ長で確かめます。`librosa.istft` は，各フレームの逆 DFT の結果にもう一度窓関数 $w[n]$ を掛け，フレームを $H$ ずつずらして足し合わせます。この操作を **重畳加算 (overlap-add)** といいます。最後に，各時刻 $n$ の値を，その時刻に重なった窓関数の 2 乗の和 $\sum_m w^2[n - mH]$ で割ります（和が 0 になる時刻では割りません）。ここでは，解説の STFT の定義式と同じく，フレーム $m$ が $x[n + mH]$（$0 \le n < N$）を切り出すとして考えます。

    1. フレーム $m$ の $X[k, m]$（$k = 0, 1, \ldots, N-1$）を逆 DFT した結果が $x[n + mH]w[n]$（$0 \le n < N$）になることを，第8回の DFT と逆 DFT の関係から説明してください。そのうえで，重畳加算の結果が，各時刻 $n$ で $x[n]\sum_m w^2[n - mH]$ になることを示してください。
    2. 1 の結果から，`librosa.istft` で元の信号 $x[n]$ が完全に再構成されるための条件を，$\sum_m w^2[n - mH]$ を使って書いてください。また，発展第3問の 3 つの条件のそれぞれがこの条件を満たすかを答えてください。
    3. 2 の条件を使って，次の 3 つの組み合わせで完全に再構成されるかを予想してください。

        - (a) 128 点のハン窓，ホップ長 112 点
        - (b) 128 点のハミング窓（`window="hamming"`），ホップ長 128 点
        - (c) 128 点の矩形窓，ホップ長 192 点

    4. `exercise/exc09_13.py` で，発展第3問と同じ `x` について 3 の組み合わせの誤差の最大値を表示し，3 の予想と比較してください。また，各組み合わせについて，$0 \le n < 1024$ の範囲での $\sum_m w^2[n - mH]$ の最小値を表示してください。この和は，長さ $1024 + N$ の配列を 0 で初期化し，$m = 0, 1, \ldots, L - 1$（$L$ はフレーム数 `D.shape[1]`）のそれぞれについて配列の $mH$ 番目から $mH + N - 1$ 番目までの要素に $w^2$ を足した後，先頭の $N/2$ 個を除いた 1024 個を取り出すと求められます（`center=True` で信号の前に $N/2$ 個の 0 を補っているためです）。窓 $w$ は `librosa.filters.get_window(window, 128)` で作ってください。
    5. 発展第3問の条件 1 のように，フレームが重ならない設定でも完全に再構成できる場合があります。それでも STFT ではハン窓とホップ長 $N/4$ や $N/2$ がよく使われる理由を，基礎第5問で見た窓の両端の形と，スペクトログラムの時間方向の細かさの 2 つの観点から説明してください。
