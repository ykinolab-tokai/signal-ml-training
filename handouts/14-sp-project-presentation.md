### 2. タスクと評価尺度

#### 入力，出力，評価尺度

タスクは，入力，出力，**評価尺度 (evaluation metric)** の 3 つで決まる。
評価尺度は，出力の良し悪しを 1 つの数値で表す規則であり，第13回の各プロジェクトで定義されている。
評価尺度には，値が大きいほどよいものと，値が小さいほどよいものがある。
この区別を，この回では評価尺度の **向き (direction)** と呼ぶ。
第13回の 4 つのプロジェクトの主評価尺度と向きは，次のとおりである。

| プロジェクト | 入力 | 出力 | 主評価尺度 | 向き |
| --- | --- | --- | --- | --- |
| 1：VAD | モノラル音声信号（$F_s=16000$ Hz） | 10 ms のフレームごとの判定 $\hat{z}[m]\in\{0,1\}$ | macro-F1 | 大きいほどよい（最大 1） |
| 2：declipping | clipped 信号 $y[n]$ としきい値 $T$ | 復元信号 $\hat{x}[n]$ | $\mathrm{SDR}_{\mathcal{C}}$ [dB] | 大きいほどよい |
| 3：burst denoising | $K$ 枚の burst 画像 | 復元画像 $\hat{x}$ | PSNR [dB]，SSIM | どちらも大きいほどよい（SSIM は最大 1） |
| 4：画像位置合わせ | 基準画像と移動画像 | 推定シフト $\hat{\boldsymbol{d}}$ | シフト誤差 $e_{\mathrm{shift}}$ の平均 [画素] | 小さいほどよい |

副評価尺度の向きも確かめておく。
declipping の $\Delta\mathrm{SDR}_{\mathcal{C}}$ と全サンプルを対象とした SDR は大きいほどよい。
$\mathrm{RMSE}_{\mathcal{C}}$，信頼できるサンプルの最大変更量 $e_{\mathcal{R}}$，clipping 制約違反率 $r_{\mathrm{viol}}$，処理時間は小さいほどよい。
画像位置合わせの成功率は大きいほどよく，シフト誤差の中央値と 95 パーセンタイル，処理時間は小さいほどよい。
1 つの表に向きの異なる評価尺度が並ぶと，「値が増えた」が改善と悪化のどちらを表すかが，列ごとに変わる。
このため，表には評価尺度の名前と単位に加えて，向きを必ず書く。

#### dB で表した評価尺度の差

PSNR は $10\log_{10}(1/\mathrm{MSE})$ であり，SDR も信号のエネルギーと誤差のエネルギーの比を $10\log_{10}$ で dB に変換した値である。
このため，同じ評価対象に対する 2 つの手法の差は，誤差のエネルギーの比として読める。
例えば，同じ画像に対する PSNR が 3 dB 高いことは，MSE が $10^{-3/10}\approx0.5$ 倍，つまり約半分になることに当たる。
差を発表するときは，「3 dB 改善した」だけでなく，誤差のエネルギーが約何分の 1 になったかも添えると，聞き手が差の大きさを判断しやすい。

#### 集計の方法

評価尺度は，どの単位で計算し，どのように集計するかまで含めて定義されている。
例えば，VAD の macro-F1 は，全 test 信号のフレームをまとめた混同行列から計算する。
declipping の主結果は，ファイルごとに計算した $\mathrm{SDR}_{\mathcal{C}}$ の平均である。
集計の方法が異なると，同じ判定結果からでも異なる値が得られる。
次の例では，音声フレームの割合が異なる 2 つのファイルについて，ファイルごとの macro-F1 の平均と，混同行列を合計してから計算した macro-F1 を比べる。

```python
def f1(tp, fp, fn):
    return 2 * tp / (2 * tp + fp + fn)

def macro_f1(tp, fp, fn, tn):
    return (f1(tp, fp, fn) + f1(tn, fn, fp)) / 2

counts = np.array([[300, 20, 30, 650],   # file a: TP, FP, FN, TN
                   [40, 60, 10, 890]])   # file b
per_file = [macro_f1(tp, fp, fn, tn) for tp, fp, fn, tn in counts]
tp, fp, fn, tn = counts.sum(axis=0)
print(np.round(per_file, 3))                                           # [0.943 0.748]
print(round(np.mean(per_file), 3), round(macro_f1(tp, fp, fn, tn), 3))  # 0.845 0.906
```

`f1` は，第13回の F1 スコアの式 $2\,\mathrm{Precision}\cdot\mathrm{Recall}/(\mathrm{Precision}+\mathrm{Recall})$ に Precision と Recall の定義を代入して整理した $2TP/(2TP+FP+FN)$ を計算する。
非音声クラスの F1 スコアは非音声を陽性とみなして計算するので，TN が TP の，FN が FP の，FP が FN の役割を持つ。
このため，`macro_f1` では，非音声クラスの F1 スコアを `f1(tn, fn, fp)` で計算している。
`for tp, fp, fn, tn in counts` は，`counts` の各行の 4 つの値を，順に 4 つの変数に代入する。
`counts.sum(axis=0)` は，TP，FP，FN，TN のそれぞれについて，2 つのファイルの値を合計する。
ファイル b は音声フレームが 1000 フレーム中 50 フレームと少なく，音声クラスの F1 スコアが低いため，ファイルごとの macro-F1 の平均（約 0.845）は，合計してから計算した値（約 0.906）より小さくなる。
比較表では，主結果を第13回の定義どおりに集計し，ファイルごとの値は条件別の内訳として示す。

### 3. ベースラインと改良手法

#### ベースライン

**ベースライン (baseline)** は，改良の効果を測るための比較の基準となる手法である。
第13回の各プロジェクトでは，ベースラインの手順が指定されている（VAD では短時間エネルギーのしきい値法，declipping では 3 次 Hermite 補間，burst denoising では算術平均，画像位置合わせでは位相相関）。
ベースラインを説明するときは，指定どおりに実装したことと，パラメータの値とその決め方を示す。
例えば，VAD のしきい値 $\theta$ と hangover の長さ $L_h$ は train（A1〜A6）の macro-F1 で決め，画像位置合わせの前処理とパラメータは dev で決めて test では固定する。
パラメータを test の結果を見て選ぶと，test での値は新しいデータに対する性能より良く見積もられるため，比較の基準として使えなくなる。
declipping の B0（処理をしない clipped 信号）のように，何も処理しない場合の値を参照値として示すと，ベースライン自体がどれだけ効いているかも伝わる。

#### 改良手法とアブレーション

改良手法は，ベースラインから変えた点として説明する。
変えた点ごとに，何を変えたか，なぜ変えたか（ベースラインのどの失敗を減らすためか），加えたパラメータの値をどのデータで決めたかを述べる。
改良手法が複数の要素を組み合わせている場合は，要素を 1 つずつ外した手法と比べて，各要素の効果を調べる。
このような比較を **アブレーション (ablation)** という。
例えば，画像位置合わせで前処理とサブピクセル推定の 2 つの要素を加えた場合は，前処理だけを外した手法と，サブピクセル推定だけを外した手法を，改良手法と同じ test のデータで評価する。
アブレーションの結果があると，どの要素がどの条件で効いたかを説明できる。

### 4. 同じ条件での比較表

#### 比較の条件をそろえる

ベースラインと改良手法の差を手法の違いによるものと説明するには，手法以外の条件をすべてそろえる必要がある。
そろえる条件は，評価に使うデータ（同じ test のファイルや画像対），評価尺度の実装と集計の方法，前処理（declipping では復元後にゲイン調整をしないこと），パラメータを決めたデータ，乱数の seed である。
例えば，burst denoising でベースラインと改良手法に別々の seed で生成したノイズを使うと，PSNR の差には，手法の違いとノイズの違いの両方が含まれる。
条件をそろえるには，同じ評価関数に 2 つの手法の出力を順に渡すコードで評価するのが確実である。

#### 評価対象ごとの結果

比較表は，評価対象ごとの値から作る。
**評価対象 (evaluation item)** は，評価尺度を 1 回計算する単位であり，1 つのファイル，1 つの画像対，1 回の burst の生成などに当たる。
1 つの評価対象と 1 つの手法の組を 1 行とする CSV に評価対象ごとの値を保存しておくと，評価をやり直さずに，条件別の集計や失敗例の抽出ができる。
この回では，すべてのプロジェクトの CSV に，手法の名前を表す `method` 列と，評価対象の名前を表す `item` 列を持たせる。
`method` 列には，`baseline` と `improved` のほか，declipping の参照値 `B0` やアブレーションの手法の名前を書く。
条件の列と評価尺度の列は，プロジェクトごとに次のとおりとする。

| プロジェクト | 評価対象（`item`） | 条件の列 | 評価尺度の列 |
| --- | --- | --- | --- |
| 1：VAD | test の 1 ファイル（A7〜A9） | なし | `tp`，`fp`，`fn`，`tn`，`macro_f1` |
| 2：declipping | test の 1 ファイル | `signal_type`，`clip_ratio` | `sdr_c`，`delta_sdr_c`，`sdr`，`rmse_c`，`e_r`，`r_viol`，`time_per_sec` |
| 3：burst denoising | 1 回の burst の生成（ノイズの seed） | `K`（ノイズの種類を変えた場合は `noise` も） | `psnr`，`ssim` |
| 4：画像位置合わせ | test の 1 画像対 | `condition`（必須条件 1〜5） | `e_shift`，`time` |

VAD の `macro_f1` 列にはファイルごとの macro-F1 を書き，`tp`，`fp`，`fn`，`tn` 列には，全ファイルで合計して主結果を計算できるように，ファイルごとの混同行列の値を書く。

#### 条件ごとの平均と標準偏差

条件ごとの結果は，その条件に含まれる評価対象の値の個数 $n$，平均 $\bar{a}$，標準偏差 $s$ で要約する。
評価対象ごとの値を $a_1,\ldots,a_n$ とすると，平均と標準偏差は次の式で計算する。

$$
\bar{a}=\frac{1}{n}\sum_{i=1}^{n}a_i,\qquad
s=\sqrt{\frac{1}{n-1}\sum_{i=1}^{n}\left(a_i-\bar{a}\right)^2}
$$

評価対象の個数は少ないことがある（VAD の test は 3 ファイル）ため，標準偏差には第6回の不偏分散に基づく式（`ddof=1`）を使う。
$n=1$ の条件では標準偏差を計算できないので，表には `-` と書き，値が 1 つしかないことが分かるようにする。
次の例では，ノイズ除去の 2 つの手法を，入力 SNR が 0 dB と 10 dB の 2 つの条件で，3 つの test 信号 s1，s2，s3 に適用した結果を扱う。
評価尺度は出力 SNR [dB] であり，大きいほどよい。
数値は説明のために作ったものである。

```python
snr = {  # output SNR [dB] of test signals s1, s2, s3
    ("baseline", "0dB"): [6.2, 5.8, 6.6],
    ("improved", "0dB"): [8.1, 7.0, 8.5],
    ("baseline", "10dB"): [13.0, 12.6, 13.3],
    ("improved", "10dB"): [13.4, 12.2, 13.9],
}
rows = []
for (method, condition), values in snr.items():
    for item, value in zip(["s1", "s2", "s3"], values):
        rows.append({"method": method, "condition": condition, "item": item, "snr_db": value})

csv_path = figure_dir / "session14_example_results.csv"
with open(csv_path, "w", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["method", "condition", "item", "snr_db"])
    writer.writeheader()
    writer.writerows(rows)

with open(csv_path, newline="") as f:
    loaded = list(csv.DictReader(f))
print(len(loaded))  # 12
print(loaded[0])    # {'method': 'baseline', 'condition': '0dB', 'item': 's1', 'snr_db': '6.2'}
```

`zip(a, b)` は，2 つのリストから同じ位置の要素を組にして，順に取り出す。
`with open(...) as f:` は，ファイルを開き，ブロックを抜けるときに自動で閉じる書き方である。
`"w"` は書き込み用に開くことを表し，`newline=""` は `csv` モジュールで改行を正しく扱うための指定である。
`csv.DictWriter` は，`fieldnames` に指定した列名の順に，辞書を 1 行ずつ書き込む。
`writeheader()` で 1 行目に列名を書き，`writerows(rows)` で辞書のリストをまとめて書き込む。
`csv.DictReader` は，各行を，列名をキーとする辞書として読み込む。
読み込んだ値はすべて文字列（`'6.2'`）なので，計算に使うときは `float()` で変換する。

次に，条件と手法の組ごとに値を集め，個数，平均，標準偏差を Markdown の表の形式で表示する。

```python
groups = {}
for row in loaded:
    key = (row["condition"], row["method"])
    if key not in groups:
        groups[key] = []
    groups[key].append(float(row["snr_db"]))

print("| condition | method | n | mean output SNR [dB] (higher is better) | std |")
print("| --- | --- | --- | --- | --- |")
for (condition, method), values in groups.items():
    values = np.array(values)
    print("| {} | {} | {} | {:.2f} | {:.2f} |".format(
        condition, method, len(values), values.mean(), values.std(ddof=1)))
```

```text
| condition | method | n | mean output SNR [dB] (higher is better) | std |
| --- | --- | --- | --- | --- |
| 0dB | baseline | 3 | 6.20 | 0.40 |
| 0dB | improved | 3 | 7.87 | 0.78 |
| 10dB | baseline | 3 | 12.97 | 0.35 |
| 10dB | improved | 3 | 13.17 | 0.87 |
```

`groups` は，条件と手法の組 `(condition, method)` をキーとし，値のリストを値とする辞書である。
キーがまだない場合は空のリストを作ってから，`append` で値を加える。
`items()` は，キーを最初に加えた順に取り出すので，表の行は CSV に現れた順に並ぶ。
条件の値を `sorted` で並べ替えると，文字列として比べられるため，`"11"` が `"3"` より前に来ることに注意する。
出力は Markdown の表の形式なので，`.md` ファイルに保存すると，VS Code のプレビューや GitHub で表として表示できる。

0 dB の条件では，改良手法の平均がベースラインより約 1.7 dB 高く，その差は各手法の標準偏差（0.40 dB，0.78 dB）より大きい。
10 dB の条件では，平均の差は 0.2 dB であり，各手法の標準偏差（0.35 dB，0.87 dB）より小さい。
平均の差が標準偏差と同じ程度以下のときは，評価対象を変えると大小が入れ替わる可能性があり，改良の効果があるとは言いにくい。

#### 評価対象ごとの差

2 つの手法を同じ評価対象に適用しているので，評価対象ごとの差を見ると，改良がどの評価対象で効き，どの評価対象で悪化したかが分かる。
差は，改良手法のほうが良い場合に正になるように定める。
大きいほどよい評価尺度では（改良手法の値 − ベースラインの値）を，小さいほどよい評価尺度では（ベースラインの値 − 改良手法の値）を差とすると，どちらの向きの評価尺度でも，正の差が改善を表す。

```python
pairs = {}
for row in loaded:
    key = (row["condition"], row["item"])
    if key not in pairs:
        pairs[key] = {}
    pairs[key][row["method"]] = float(row["snr_db"])

keys = list(pairs)
gain = np.array([pairs[k]["improved"] - pairs[k]["baseline"] for k in keys])  # higher is better
print(np.round(gain, 2))            # [ 1.9  1.2  1.9  0.4 -0.4  0.6]
print(np.sum(gain < 0), len(gain))  # 1 6
order = np.argsort(gain)
for i in order[:2]:
    print(keys[i], round(gain[i], 2))
```

```text
('10dB', 's2') -0.4
('10dB', 's1') 0.4
```

`pairs` は，`(condition, item)` の組をキーとし，手法の名前から値を引く辞書を値とする，入れ子の辞書である。
`list(pairs)` は，辞書のキーを加えた順に並べたリストを返す。
`np.argsort(gain)` は，`gain` を小さい順に並べたときの添字の配列を返す。
したがって，`order[:2]` は，改善が最も小さい（悪化が最も大きい）2 つの評価対象の添字である。
6 つの評価対象のうち，改良手法がベースラインより悪くなったのは，10 dB の条件の s2 だけである。
条件ごとの平均だけを示すと，この悪化は見えない。
このように悪化した評価対象は，第6節で扱う失敗例の候補になる。

### 5. 根拠としての図と音

#### 主張と見る場所を先に述べる

図と音は，主張の根拠として選ぶ。
図を見せる前に，何を主張するための図か（例：「改良手法では，clipping 区間の山の高さが清浄信号に近づいた」）と，図のどこを見ればよいか（横軸の範囲，画像の領域，相関面のピーク）を述べる。
見る場所を先に述べないと，聞き手は図の別の場所を見てしまい，主張と図の対応が伝わらない。
プロジェクトごとの図と音の例と，見る場所は次のとおりである。

| プロジェクト | 図・音 | 見る場所 |
| --- | --- | --- |
| 1：VAD | 波形，正解ラベル，判定結果 $\hat{z}[m]$，スコア $S[m]$ としきい値 $\theta$ を，時間軸をそろえて縦に並べた図 | 発話の始まりと終わり，発話の間の短い無音，誤判定が続く区間 |
| 2：declipping | clipping 区間を含む 20〜50 ms の波形拡大図（清浄信号，clipped 信号，復元信号），誤差信号，STFT スペクトログラム，復元音 | clipping 区間の山や谷の形，誤差が大きいサンプル，clipping によって生じた高い周波数の成分 |
| 3：burst denoising | 同じ領域を切り出した原画像，burst の 1 枚，ベースラインと改良手法の復元画像，誤差画像 $\lvert x-\hat{x}\rvert$ | 輪郭や細かい模様のぼけ，平坦な領域に残ったノイズ |
| 4：画像位置合わせ | 基準画像，移動画像，推定シフトで位置合わせした後の差分画像，相関面 $\lvert r\rvert$ | 差分画像に残る輪郭，相関面のピークの数と高さ |

#### 比べられる図にする

ベースラインと改良手法の図は，同じ評価対象の同じ範囲を，同じ縦軸の範囲で描く。
2 次元配列（1 チャネルの画像）を `imshow` で表示するときは，`vmin` と `vmax` を指定して色の範囲をそろえる。
`imshow` は，`vmin` と `vmax` を指定しないと，画像ごとにその最小値と最大値を色の両端に割り当てる。
このため，誤差の大きさが異なる 2 枚の誤差画像が，同じ程度の誤差に見えてしまう。
次の例では，第4節の評価対象ごとの値を，条件ごとに 1 つの図に描く。

```python
fig, axes = plt.subplots(1, 2, figsize=(8, 4))
for ax, condition in zip(axes, ["0dB", "10dB"]):
    for item in ["s1", "s2", "s3"]:
        values = [pairs[(condition, item)]["baseline"], pairs[(condition, item)]["improved"]]
        ax.plot([0, 1], values, marker="o", label=item)
    ax.set_xticks([0, 1], labels=["baseline", "improved"])
    ax.set_title("input SNR " + condition)
    ax.set_ylabel("output SNR [dB]")
    ax.legend()
    ax.grid(True)
fig.tight_layout()
fig.savefig(figure_dir / "session14_example_paired.png")
plt.show()
plt.close(fig)
```

各線は 1 つの評価対象を表し，左端がベースライン，右端が改良手法の値である。
出力 SNR は大きいほどよいので，右下がりの線は，改良手法で悪化した評価対象を表す。
右の図では，s2 の線だけが右下がりになっている。
`ax.set_xticks(位置, labels=名前)` は，横軸の目盛りの位置と名前を指定する。
1 つの図の中では 2 つの手法を同じ縦軸で比べているが，左右の図では縦軸の範囲が異なる。
このため，線の傾きの見た目から，改善の大きさを左右の図で比べてはいけない。
条件の間で値を比べる図では，`plt.subplots(1, 2, sharey=True)` のように `sharey=True` を指定して縦軸をそろえる。

#### 音で示す

音で示すときは，聞く順序（例：清浄信号，clipped 信号，ベースライン，改良手法）と，聞いてほしい点（例：clipping 区間のひずみが残っているか）を先に述べる。
比べる音は，すべて同じ倍率のまま保存する。
ファイルごとに最大振幅が 1 になるように正規化すると，大きさの違いを聞き比べられなくなる。
また，`sf.write` は WAV を既定で 16 bit の整数（`PCM_16`）として保存するため，$[-1,1]$ の範囲を超える値は範囲の端の値に切り取られる。
復元信号の振幅が 1 を超えることがある場合は，`subtype="FLOAT"` を指定して，浮動小数点数のまま保存する。

```python
fs = 16000
t = np.arange(160) / fs                        # 10 ms
restored = 1.2 * np.sin(2 * np.pi * 200 * t)  # peak amplitude exceeds 1
sf.write(figure_dir / "session14_example_pcm16.wav", restored, fs)
sf.write(figure_dir / "session14_example_float.wav", restored, fs, subtype="FLOAT")
x16, _ = sf.read(figure_dir / "session14_example_pcm16.wav")
x32, _ = sf.read(figure_dir / "session14_example_float.wav")
print(round(np.max(restored), 3), round(np.max(x16), 3), round(np.max(x32), 3))  # 1.2 1.0 1.2
```

`sf.read` は信号とサンプリング周波数の 2 つを返す。
`_` は，使わない値を受け取る変数名として慣例的に使う。
既定の 16 bit で保存したファイルでは，最大値 1.2 が約 1.0 に切り取られている。
`subtype="FLOAT"` で保存したファイルでは，1.2 が保たれている。

### 6. 失敗例の分析

#### 失敗例の選び方

**失敗例 (failure case)** は，手法が期待どおりに動かなかった評価対象である。
失敗例は，印象で選ばず，規則に従って選ぶ。
例えば，「改良手法の主評価尺度が最も悪い 3 つの評価対象」や「改良手法がベースラインより悪くなった評価対象」のように選ぶ。
規則に従って選ぶと，失敗例がどれだけ一般的か（例：25 個の画像対のうち 3 個）も示せる。
第4節の例のように，評価対象ごとの差を小さい順に並べると，改良手法で悪くなった評価対象を見つけられる。
ただし，主評価尺度が最も悪い評価対象は，手法の失敗ではなく，条件の難しさ（burst denoising の小さい $K$ など）を表していることもある。

#### 仮説と確認

失敗例を見つけたら，その原因の **仮説 (hypothesis)** を立てる。
仮説は確かめられる形で書く。
そのために，「仮説が正しければ，どのような結果が観察されるはずか」という予測を仮説から導き，その予測と実際の結果を比べる。
例えば，次のような仮説と予測の組が考えられる。

| プロジェクト | 仮説 | 仮説が正しい場合に観察されるはずのこと |
| --- | --- | --- |
| 1：VAD | 語尾の弱い子音が非音声と判定されている | 音声を非音声と誤判定したフレームが，正解の音声区間の終わりの付近に集中する |
| 2：declipping | 長い clipping 区間では，両端の値と傾きだけでは山の形を表せない | 長い区間ほど $\Delta\mathrm{SDR}_{\mathcal{C}}$ が小さい |
| 3：burst denoising | 改良手法で加えたフィルタが，輪郭や細かい模様をぼかしている | PSNR の改善が，平坦な領域では大きく，輪郭の多い領域では小さい |
| 4：画像位置合わせ | 周期的な模様があると，相関面に高さの近いピークが複数できる | 失敗した画像対では，2 番目に高いピークと最も高いピークの高さの比が 1 に近い |

予測と結果を比べるときは，失敗例 1 つだけでなく，仮説の原因を持つ評価対象と持たない評価対象の両方の値を比べる。
例えば declipping では，clipping 区間を区間長で分け，長い区間と短い区間で $\Delta\mathrm{SDR}_{\mathcal{C}}$ の平均を比べる。
失敗例の図を 1 枚見せるだけでは，その評価対象で起きたことは分かっても，同じ原因を持つ他の評価対象でも同じように失敗するかは分からない。
予測と結果が一致しなかった場合は，その仮説を棄却し，別の仮説を立てる。
時間内に確かめられなかった仮説は，確かめていないことを明記して示す。

#### 失敗例の記録

失敗例は，次の 5 項目で記録する。
この順に書くと，事実と推測を区別して説明できる。

1. 事実：どの評価対象で，評価尺度の値がいくつになったか（図のファイル名）
2. 仮説：原因は何と考えられるか
3. 予測：仮説が正しければ，何が観察されるはずか
4. 確認：実際に何を計算し，どのような値が得られたか（ファイル名と値）
5. 結論：仮説は支持されたか，棄却されたか

### 7. 質疑と再実行の記録

#### 質疑の記録

質疑では，質問，自分の回答，回答の根拠として表示したファイルを組にして記録する。
その場で答えられなかった質問や，回答に自信がない質問には，確認に使う結果ファイルやコードと，確認のために計算する値を書いておく。
例えば，第4節の例で「10 dB の条件で s2 だけが悪化した理由は何か」と聞かれて答えられなかった場合は，確認に使うものとして `outputs/exc14/session14_example_results.csv` の s2 の行と，s2 に 2 つの手法を適用するコードを挙げる。
そのうえで，「s2 の 10 dB の条件で，2 つの手法の出力の誤差のスペクトルを比べる」のように，計算する値を書く。
発表の前には，比較の条件（パラメータを test で選んでいないか），結果の一般性（他のデータでも同じ傾向になるか），差の大きさ（ばらつきと比べて十分か）を聞かれた場合に表示するファイルを決めておく。

#### 再実行の方法

他の人が同じコードとデータから同じ結果を作り直せることを，**再現性 (reproducibility)** という。
発表で示した結果に再現性があることを示すため，再実行の方法には次の項目を書く。

| 項目 | 書く内容 |
| --- | --- |
| 実行環境 | Python 環境の準備方法（[共通手順](README.md#python環境の準備更新と演習の実行) の `uv sync --locked`），OS 側で必要な準備 |
| 入力データ | データの置き場所（例：`data/declipping/`）と，入手または作成の方法 |
| 実行コマンド | 作業リポジトリのルートで実行するコマンド（実行する順） |
| パラメータと seed | 決めたパラメータの値（$\theta$，$L_h$ など）と，乱数の seed |
| 出力 | 作られるファイル名と，それぞれの内容 |
| 所要時間 | 自分の PC での実行時間 |

コマンドは，説明の文章ではなく，そのままコピーして実行できる形で書く。
自分の PC の絶対パスは書かず，作業リポジトリのルートからの相対パスで書く。
書いた手順で結果を作り直せるかは，新しいターミナルで手順のコマンドだけを実行し，作り直した評価対象ごとの CSV が元の CSV と一致するかで確かめる。
評価尺度の値は，同じ PC で同じデータ，パラメータ，seed を使えば一致するはずだが，処理時間は実行のたびに変わるので，一致を確かめる対象から除く。
作業リポジトリを別のディレクトリに clone し直して確かめる方法は，第27回で扱う。

        - burst denoising：`psnr` と `ssim` を，それぞれ `key="K"` で集計した 2 つの表。ノイズの種類を変えた場合は，`noise` の値ごとに行を分けてから集計する。

    5. 4 の表の主結果（VAD では合計して計算した macro-F1，declipping では `key=None` の `sdr_c` の平均，burst denoising では $K$ ごとの値，画像位置合わせでは `key=None` の `e_shift` の平均）が，第13回で報告した値と一致することを確かめてください（4 で dev のデータを使った場合は，第13回で dev について求めた値と比べてください）。一致しない場合は，評価に使ったデータ，パラメータ，seed，集計の方法のどれが異なるかを調べ，その結果を `exercise/exc14_01.md` の `## 結果` に書いてください。
    6. `exercise/exc14_01.md` の `## 結果` に，表のファイル名と，表から読み取れること（どの条件で，どちらの向きに，標準偏差と比べてどの程度の差があったか）を 3 行以内で書いてください。
    7. 1 の 8 行の `noise` の条件では，改良手法の平均のほうが良いにもかかわらず，p1 では改良手法のほうが悪くなっています。`occlusion` の条件の結果と合わせて，平均の差だけで「改良手法が良い」と結論できない理由を，3 の表の `n` と `std` の列を使って説明してください。また，表に向きを書かないと聞き手が誤解するおそれがある例を，自分のプロジェクトの評価尺度（解説の第2節の副評価尺度を含む）を使って 1 つ挙げてください。

3. 失敗例を規則に従って選び，原因の仮説と，それを確かめるために見た結果を対応づけます。第2問の評価対象ごとの CSV を使い，主評価尺度は，VAD ではファイルごとの `macro_f1`，declipping では `sdr_c`，burst denoising では `psnr`，画像位置合わせでは `e_shift` とします。

    1. 改良手法がベースラインより悪くなった評価対象がいくつあるかと，改良手法の値が最も悪い評価対象がどれかを予想してください。
    2. `exercise/exc14_03.py` で，評価対象ごとに `baseline` と `improved` の値を対応づけ，`item`，`baseline`，`improved`，`gain` の 4 列の CSV を `outputs/exc14/exc14_03.csv` に保存してください。`gain` は，第2問と同じく改良手法のほうが良い場合に正になる差とし，行は `gain` の小さい順に並べてください。burst denoising では `K` と `item` の組を 1 つの評価対象とし，`item` 列には `K3_seed0` のように両方を書いてください。
    3. `gain` が負の評価対象の個数と全体の個数，`gain` が最も小さい 3 つの評価対象，改良手法の値が最も悪い 3 つの評価対象を，値とともに表示してください。最も悪い順は，大きいほどよい評価尺度では値の小さい順，小さいほどよい評価尺度では値の大きい順とします。1 の予想と比較してください。
    4. 3 で表示した評価対象から失敗例を 1 つ選び，ベースラインと改良手法の結果を並べた図を `outputs/exc14/exc14_03.png` に保存してください。図の内容は解説の第5節の表から選び，2 つの手法の図の縦軸の範囲（画像では `vmin` と `vmax`）をそろえてください。
    5. `exercise/exc14_01.md` の `## 失敗例と考察` に，解説の第6節の 5 項目（事実，仮説，予測，確認，結論）を書いてください。確認では，仮説の原因を持つと考えられる評価対象と持たないと考えられる評価対象の値を，2 の CSV または第13回の結果を使って比べてください。
    6. 予測と確認の結果が対応していることを確かめてください。対応していない場合は，仮説を棄却して別の仮説を書いてください。また，4 の図だけでは仮説を確かめたことにならない理由を，自分の失敗例に即して説明してください。

4. 発表で受けた質問を，確認に使う結果ファイルやコードと結びつけて記録します。記録は `exercise/exc14_04.md` に書くものとします。

    1. 発表の前に，聞き手から出そうな質問を 2 つ予想し，`exercise/exc14_04.md` の `## 想定質問` に書いてください。1 つは比較の条件（test のデータ，パラメータを決めたデータ，seed）に関する質問とし，それぞれに答えるときに表示するファイル名を添えてください。
    2. 発表中または発表の直後に，受けた質問と自分の回答を，`## 質疑` に 1 問ずつ書いてください。各回答には，根拠として表示したファイル名，または表示すべきだったファイル名を添えてください。
    3. 答えられなかった質問と，回答に自信がない質問には，確認に使う結果ファイルまたはコード（ファイル名と関数名）と，確認のために計算する値を書いてください。
    4. 1 の想定質問と実際の質問を比べてください。予想していなかった質問があれば，`exercise/exc14_01.md` のどの見出しに何を書いておけば答えられたかを書き，そう考えた理由を説明してください。
